# Phase 3: Release Layer Implementation Plan (fastlane, release workflows, release-please, OTA)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the template a professional, symmetric store-release pipeline: one build per main merge (TestFlight internal + Play internal + GitHub pre-release), promotion of that same build to beta on a release-please release, gated phased production, OTA via expo-updates behind a toggle, human-readable store notes with an optional LLM rewrite — all dry-run verifiable without store credentials, and live-verifiable when credentials are present in the environment.

**Architecture:** Fastlane lives in the template's root `fastlane/` (ios/android are regenerated by prebuild). Versioning: release-please owns version/CHANGELOG/tag/release; internal builds derive the pending version; build number = first-parent commit count + offset. Reusable mechanics (`expo-prepare`, `expo-build-ios/android`, `fastlane-lane`, `github-release`, `expo-ota-publish`) live in `react-native-workflows`; the template keeps thin policy workflows. Verification gates run after every build and before any upload.

**Tech Stack:** fastlane 2.238 (pilot/deliver/supply/match/gym/gradle, Spaceship), Ruby 3.3 + bundler, bundletool, apksigner/aapt2 (Android SDK build-tools), `@expo/fingerprint`, expo-updates code signing, release-please-action v5, GitHub Environments, xprem (self-hosted OTA server, Docker), Node 24 (`node:test`, fetch-based LLM adapters).

**Spec:** `docs/superpowers/specs/2026-09-06-react-native-template-family-design.md` — Part B in full (lanes, versioning, release notes, workflows, channel model, OTA server, verification gates, secrets, runbook, OTA toggle) and the Phase 3 section. Depends on Phase 2's `react-native-workflows` (`setup` and `native-key` actions, `.rnw` self-checkout, `RNW` env, `scripts/lib/{common,versions,expo-config}.sh`).

### Task 2 (template): Versioning, build info, fingerprint, OTA toggle, app.config wiring

- [ ] `scripts/release/resolve-version.sh`:
```bash
#!/usr/bin/env bash
# Prints APP_VERSION and APP_BUILD_NUMBER (KEY=VALUE lines; also to $GITHUB_OUTPUT when set).
# Version: HEAD tag vX.Y.Z → X.Y.Z; else open release-please PR ("chore(main): release X.Y.Z") → X.Y.Z; else last tag patch+1.
# Build number: first-parent commit count + BUILD_NUMBER_OFFSET (default 1000).
set -euo pipefail
cd "${1:-.}"
offset="${BUILD_NUMBER_OFFSET:-1000}"
count=$(git rev-list --count --first-parent HEAD)
build=$((count + offset))
version=""
tag=$(git tag --points-at HEAD | grep -E '^v[0-9]+\.[0-9]+\.[0-9]+$' | head -1 || true)
if [ -n "$tag" ]; then version="${tag#v}"
elif [ -n "${RELEASE_PR_TITLE:-}" ]; then version=$(printf '%s' "$RELEASE_PR_TITLE" | grep -oE '[0-9]+\.[0-9]+\.[0-9]+' | head -1 || true)
elif command -v gh >/dev/null 2>&1 && [ -n "${GH_TOKEN:-}" ]; then
  version=$(gh pr list --state open --label 'autorelease: pending' --json title -q '.[0].title' 2>/dev/null | grep -oE '[0-9]+\.[0-9]+\.[0-9]+' | head -1 || true)
fi
if [ -z "$version" ]; then
  last=$(git tag -l 'v[0-9]*' --sort=-v:refname | head -1); last="${last#v}"; last="${last:-0.0.0}"
  IFS=. read -r a b c <<<"$last"; version="$a.$b.$((c + 1))"
fi
printf 'APP_VERSION=%s\nAPP_BUILD_NUMBER=%s\n' "$version" "$build"
if [ -n "${GITHUB_OUTPUT:-}" ]; then printf 'version=%s\nbuild-number=%s\n' "$version" "$build" >> "$GITHUB_OUTPUT"; fi
```
